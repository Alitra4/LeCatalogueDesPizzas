# LeCatalogueDesPizzas

# Le Projet : Le Catalogue Des Pizzas

le but du projet est de répertorier plusieurs pizzas dans un catalogue avec des informations qui leurs seront asssociés, afin de pouvoir en savoir plus sur la pizza et tout son univers

# Etape 1 : initialisation du frontend

L'objectif est d'initialiser un projet vite dans un dossier nommé frontend afin de pouvoir travailler sur le frontend et d'avoir un visuel sur le navigateur de notre travail (ici, pas de difficultés rencontrées)

# Etape 2 : initialisation du backend

De même, il s'agit de créer le projet backend à l'aide d'expressJS (cloné depuis un repository template) dans un dossier nommé backend afin de pouvoir créer la base de données, et de la lié au projet frontend (ici, j'ai réussi à initialiser le projet backend à partir du repository template cloné, j'ai également installé express, @types/express, dotenv et j'ai commencé à prendre en main le fichier contenant les données, mais je n'ai pas encore saisi le lien avec PostgreSQL, pgAdmin, ni comment créer une base de données à partir de ça, wip...)

# Etape 3 : Créer un repository Github

Pour cette étape, il s'agit de partager le travail (tout le tavail, c'est à dire le dossier LeCatalogueDesPizzas) sur github (ici, aucune difficultés rencontrés)

# Etape 4: Créer une base de données

L'idée ici est de créer une base de données dans SQLectron afin de rasembler toutes les données pour le backend du projet (ici, pas de difficultées rencontrées)

# Etape 5 : Lier la base de données au backend

L'objectif est de lier la base de données au backend afin de pouvoir à terme le manipuler dans le frontend (ici, j'ai réussie à écrire le lien entre la base de données et le backend et je n'ai pas réussie à intégrer les informations de connexion au serveur SQLectron, wip... (ça y est j'ai compris, uniquement des erreur de syntaxe))

# Etape 6 : Lier le backend au frontend

De même, il s'agit de lier le backend au frontend afin d'envoyé, d'afficher puis de manipuler les informations de la base de données sur l'interface utilisateur (ici, j'ai réussie à écrire quasi-tout l'appel d'api, il ne me reset plus qu'à comprendre pourquoi ça n'affiche rien, et aussi le fonctionnement du log[] dans le useState pour pouvoir l'utiliser au mieux sans avoir d'erreurs (c'est bon, je n'avais pas fait de typage de l'API + quelques erreurs de syntaxe (je dev je junior :p )))

# Etape 7 : Afficher une seule tulpe

Pour cette étape, il faut créer une route entre App.tsx et les differents composants, puis de lier (avec un get.app) un Link de la HomePage à une tulpe spécifique du backend (ici, aucune difficultés rencontrées, hormis d'éternels erreurs de syntaxe, de ponctuation et autres parenthèses...)
